# Paperflow 管理平台页面功能说明

本文面向管理平台使用者，说明当前每个页面能查看、检索或管理什么信息，以及这些能力能解决什么问题。

## 使用范围与边界

Paperflow 管理平台用于查看 Paperflow 业务数据和文件资源，并提供受控的 OpenAlex
来源元数据导入任务入口。Java 服务不执行导入逻辑；它只创建和展示任务，独立 Python
worker 执行 OpenAlex Metadata Import。平台不会执行原始文件采集、Matching、Text
Parsing、Block Import 或 MinerU。

页面中出现的“论文”对应项目术语 **Work**，即 OpenAlex 论文记录；“来源期刊”对应 **Source**，即 OpenAlex 出版来源；“原始文件”是本地存储的论文源文件。状态含义如下：

- 匹配：原始文件是否已关联到 Work。
- 文件解析：PDF 是否已由 MinerU 解析为结构化输出；XML 与 HTML 在当前版本属于不支持解析的输入，不代表解析失败。
- 全文入库：已解析内容是否已写入全文块（Block）相关表；它独立于文件解析状态。

所有已登录用户都可使用业务、服务和知识管理页面。系统管理中的用户管理仅 `SUPER_ADMIN` 和 `ADMIN` 可见；角色管理和操作审计仅 `SUPER_ADMIN` 可见。

## 登录与账户

### 登录页（`/login`）

- 使用管理平台账号和密码登录，并在登录后回到原先请求的页面或工作台。
- 建立受登录态和 CSRF 保护的会话，避免未登录用户直接访问管理页面。
- 为平台使用者提供受控访问入口；登录失败时提示检查账号和密码。

### 账户菜单（所有已登录页面右上角）

- 支持修改当前账号密码，需要填写当前密码和新密码。
- 支持退出登录，结束当前会话并回到登录页。
- 密码修改和退出操作会记录在操作审计中，便于追溯账号相关操作。

## 工作台

### 工作台（`/task-status`）

- 汇总来源期刊数、Work 数、原始文件数、匹配成功 Work 数、已解析文件数和全文已入库文件数，帮助用户快速判断整体数据覆盖和处理进度。
- 以来源期刊为粒度展示论文匹配、文件解析和全文入库的完成率，可直观看出处理滞后的来源。
- 支持按来源期刊名称、来源期刊 ID、平台筛选，并可按数据量或各阶段进度排序，便于定位优先排查对象。
- 可跳转到对应的来源期刊详情，继续查看其 Work 和原始文件。

## 文献资源

### OpenAlex 来源检索（`/source-search`）

- 按来源名称、Source ID、ISSN 或出版社检索 OpenAlex Source。
- 展示 Source ID、ISSN、出版社、Works 数、开放获取标记与来源主页，帮助确认导入目标。
- `ADMIN` 与 `SUPER_ADMIN` 可为单个 Source 创建元数据导入任务，年份范围可选；留空即导入该 Source 全部年份。
- 显示该 Source 的最近导入任务、执行进度、导入计数和安全的失败摘要；失败任务可重试。
- 导入只更新 Source、Work、作者、来源关联与主题元数据，不采集原始全文，也不执行匹配、解析或全文入库。

### 来源期刊列表（`/sources`）

- 分页列出 Source 的 ID、名称、所属平台，以及 Work、原始文件、已匹配、已解析、就绪、解析失败、全文入库失败和不支持解析文件的数量。
- 支持按名称、ID、平台、有无原始文件、有无失败筛选，并可按 ID、Work 数或失败数排序。
- 支持按当前筛选条件导出 UTF-8 CSV，方便在表格软件或外部分析工具中继续汇总。
- 点击来源期刊 ID 可进入详情页。

### 来源期刊详情（`/sources/:sourceId`）

- 展示单个 Source 的基本信息和全部处理统计，帮助用户判断该来源的文件覆盖、解析成功率与失败规模。
- 提供“查看论文”和“查看原始文件”入口，并自动带入来源期刊 ID 筛选条件，便于从汇总钻取到具体记录。

### 论文列表（`/works`）

- 分页查看 Work 的 ID、标题、DOI、发表年份、所属来源期刊、处理状态及关联原始文件的各阶段状态。
- 支持按标题、Work ID、DOI、来源期刊 ID/名称、作者、发表年份区间和处理状态检索。
- 支持按发表时间、标题、ID 或状态优先级排序，可优先发现异常或确认就绪数据。
- 支持按当前筛选条件导出 UTF-8 CSV，并可进入单篇 Work 详情。

### 论文详情（`/works/:workId`）

- 查看 Work 的标题、DOI、发表日期、类型、语言和当前处理状态。
- 查看关联的来源期刊和作者列表，帮助用户核验 OpenAlex 元数据。
- 展示已匹配原始文件的文件信息及匹配、解析、全文入库状态；可继续跳转到该文件详情。
- 当该 Work 存在因果声明时，展示声明记录数、标准变量对数和变量数，并可跳转到论文因果声明页。
- 提供解析后全文和匹配原始文件的入口，形成从元数据到文件内容的排查链路。

### 论文全文（`/works/:workId/blocks`）

- 以阅读形式展示该 Work 关联文件导入后的全文块，而不是只显示原始数据库字段。
- 根据块类型渲染标题、正文、图片、表格、公式、参考文献和页脚注释；图片、表格和公式会显示已保存的资源或结构化内容。
- 可选择“包含丢弃块”，用于比对正常阅读内容和解析阶段被标记为丢弃的内容。
- 用于人工核验解析后的全文结构、表格和公式是否可用。

### 原始文件列表（`/original-files`）

- 分页列出 Original File 的 ID、所属来源期刊、类型、文件名、大小、已匹配 Work，以及匹配、文件解析和全文入库状态。
- 支持按来源期刊、平台、已匹配 Work、原始文件类型、年份区间及三类阶段状态筛选。
- 支持按来源、年份、文件大小、平台或解析异常优先排序，帮助快速定位异常文件或特定批次。
- 支持按当前筛选条件导出 UTF-8 CSV；可从来源、Work 和文件 ID 在不同上下文间跳转。

### 原始文件详情（`/original-files/:fileId`）

- 查看原始文件的路径、大小、来源、采集元数据（标题、作者、DOI、URL、平台、年份）和各处理阶段状态。
- 提供原始文件下载/打开链接，以及解析生成的文本文件列表和对应资源链接。
- 可跳转到匹配的 Work 详情或该文件的解析后全文，用于核验“文件 - Work - 内容块”的关联关系。

### 解析后全文（`/original-files/:fileId/blocks`）

- 按指定 Original File 展示其已入库的全文块，渲染规则与“论文全文”一致。
- 支持包含丢弃块，适合从文件处理角度检查具体文件的解析、表格、图片和公式结果。

## 系统管理

### 用户管理（`/users`）

- 查看平台账号的用户名、显示名、角色、启用状态、最近登录时间和创建时间。
- 创建账号，并设置显示名、初始密码、角色和是否立即启用。
- 启用或禁用已有账号，重置其密码，满足账号交接和访问回收需要。
- `SUPER_ADMIN` 可分配 `SUPER_ADMIN`、`ADMIN` 和 `USER` 三种角色；`ADMIN` 只能创建或管理 `USER` 角色账号。`USER` 无权进入本页面。

### 角色管理（`/roles`）

- 展示当前固定角色及权限说明：`SUPER_ADMIN` 具备完整系统管理权限，`ADMIN` 可管理 `USER` 账号，`USER` 为只读管理台使用者。
- 用于确认当前平台的权限边界。角色为固定集合，不提供自定义角色或动态权限配置。
- 仅 `SUPER_ADMIN` 可访问。

### 操作审计（`/audit-logs`）

- 查询登录、退出登录、修改密码、创建用户、更新用户和重置密码等管理操作。
- 支持按操作人、操作类型、目标类型、结果、请求 ID 和操作时间范围筛选。
- 每条记录展示操作时间、操作者、目标、成功/失败结果、请求 ID、来源 IP 与说明，可用于追溯账号管理行为和关联服务错误。
- 仅 `SUPER_ADMIN` 可访问。

## 服务管理

### 服务状态（`/service-status`）

- 汇总后端、数据库、`DATA_ROOT` 可读性和磁盘空间检查结果，并展示应用版本与检查时间。
- 当任一检查异常时给出整体异常状态，帮助运维人员迅速区分应用、数据库、文件目录或存储容量问题。
- 展示最近接口错误的时间、请求 ID、请求方法、路径和错误信息，便于使用请求 ID 在日志系统中继续排查。

### 失败任务（`/failure-tasks`）

- 聚合列出 Matching、Text Parsing 或 Block Import 失败的 Original File，并以来源期刊名称/ID和失败阶段筛选。
- 展示文件、来源、匹配 Work 及三个阶段状态，提供文件和 Work 上下文入口。
- 对每条失败记录生成可复制的 CLI 建议命令：匹配使用 `paperflow match`，解析重试使用 `paperflow parse-text`，内容块入库重试使用 `paperflow import-blocks`。
- 页面只提供排查和命令建议，不会从浏览器触发 pipeline 或修改业务状态；命令必须在具备相应运行环境的运维侧执行。

### Swagger（`/swagger-ui/index.html`）

- 在新标签页打开后端 Swagger UI，供开发、集成和运维人员浏览 REST API 合约并进行接口调试。
- 此入口面向 API 使用者，不替代管理页面的权限与业务操作边界。

## 知识管理

### 因果知识图谱（`/knowledge/causal-graph`）

- 展示因果声明抽取记录、标准关系、论文和变量的总体数量，以及当前筛选结果中的节点和关系数。
- 可按变量关键词、最小重复记录数、最小方法数、子领域、最大节点数和最大边数筛选图谱预览；变量输入提供术语补全。
- 可直接输入原因变量和结果变量查询一条指定因果关系。
- 通过力导向图查看变量和关系网络，并在下方查看当前结果中最高频的关系、其记录数、论文数、方法数和主导方向。
- 可跳转到变量或关系详情，用于从宏观网络钻取到可核验的证据。

### 变量详情（`/knowledge/causal-graph/nodes/:variable`）

- 展示变量的总声明记录数、作为原因和结果出现的次数，以及主导子领域。
- 以局部图谱呈现该变量周边关系，并分别列出出边和入边。
- 每条关系提供记录数、论文数、方法数和主导方向，支持跳转到关系证据详情。

### 关系详情（`/knowledge/causal-graph/edges?cause=...&effect=...`）

- 查看某个标准化“原因变量 -> 结果变量”的聚合信息，包括记录数、支持论文数、方法多样性以及正向、负向、不显著和混合方向的分布。
- 列出关系对应的证据记录，便于回溯每条因果声明及其论文来源。
- 当不存在证据时明确显示空结果，避免将未收录的关系误解为加载故障。

### 论文因果声明（`/knowledge/causal-graph/papers/:workId`）

- 聚合展示单篇 Work 的因果声明数量、局部图谱节点数、关系数和核心发现数量。
- 在局部力导向图中观察论文内部的变量与因果关系。
- 以表格查看标准关系、方向、因果推断方法、显著性和原始主张；核心发现优先显示，展开行可查看证据文本。
- 提供返回 Work 详情和查看解析后全文的入口，使知识图谱结论可以回链到论文元数据与正文。

### 领域分析（`/knowledge/causal-graph/fields`）

- 从领域、主题两个维度统计因果声明记录数、论文数和变量数，并支持分别按子领域和主题过滤。
- 展示全局高频关系、高频变量和因果推断方法分布，帮助用户比较不同研究领域的知识覆盖与证据方法。
- 高频关系和变量可直接跳转到相应详情页，继续核验具体关系与变量。

## 页面间的常见使用路径

1. 从“工作台”发现某个来源期刊的处理进度异常，进入来源详情，再进入 Work 或原始文件列表定位记录。
2. 从“失败任务”复制适用的运维命令处理失败，处理完成后回到原始文件详情、解析后全文或工作台核验结果。
3. 从“论文详情”确认元数据、作者和匹配文件，再查看全文块或论文因果声明，完成从 Work 到正文和知识证据的追溯。
4. 从“因果知识图谱”发现变量或关系，进入详情查看证据，再跳转到对应 Work 的因果声明和全文进行人工核验。
