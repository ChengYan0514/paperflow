# Paperflow 管理台成熟度缺口

本文记录 `java-admin` 后端和 `web-admin-pro` 前端相对于成熟管理平台仍欠缺的能力。

当前项目已经具备只读业务看板、账号管理、来源/Work/Original File/全文块查看、服务状态、操作审计、失败任务只读处理建议、CSV 导出、OpenAPI 合约和自动化测试。主要缺口不在基础 CRUD，而在更深的搜索、错误体验、权限治理和生产部署能力。

## 当前定位

`README.md` 明确当前平台是只读管理平台：

- 读取 Paperflow PostgreSQL 表。
- 读取 `DATA_ROOT` 下的文件资源。
- 只写本地 `admin_user` 和 `admin_audit_log` 管理表。
- 不导入数据。
- 不触发 Python pipeline。
- 不运行 MinerU。
- 不写 Paperflow 业务表。

因此，下面建议分为当前只读定位内应补的能力，以及未来如果升级为运营控制台才需要的能力。

## 已补齐

### 1. 服务状态页真实接入

现状：已完成。`/service-status` 由 `GET /api/service-status` 驱动，展示：

- Java 后端健康状态。
- 数据库连接状态。
- `DATA_ROOT` 是否存在、是否可读。
- 磁盘空间。
- 当前版本号。
- 最近错误摘要。

仍可后续增强：接入 Actuator 指标、构建提交号和更完整的日志聚合。

### 2. 操作审计日志

现状：已完成。新增 `admin_audit_log`，并提供 `GET /api/admin-audit-logs` 给
`SUPER_ADMIN` 查询。

当前记录：

- 操作人。
- 操作类型。
- 操作目标。
- 操作结果。
- requestId。
- IP / User-Agent。
- 操作时间。

已覆盖登录失败、登录成功、退出登录、创建用户、更新用户、重置密码、修改密码。

### 3. 失败任务处理闭环

现状：已完成只读版本。新增 `/failure-tasks`，复用 Original File 列表筛选失败项，
展示失败状态解释、上下文入口和可复制 CLI 建议命令。

当前仍保持只读边界：

- 不触发 Python pipeline。
- 不写 Paperflow 业务表。
- 不重置 `original_file_job` 状态。

如果未来放开写操作，再考虑重试/重置按钮。

### 4. 导出能力

现状：已完成三大列表导出。`/sources`、`/works`、`/original-files` 支持按当前筛选导出 UTF-8 CSV。

失败任务页当前没有单独导出按钮；需要时可复用 Original File 导出端点加失败筛选参数。

## 优先补齐

### 1. 全局搜索 / 块搜索

现状：`/block-search` 是占位页面。

成熟平台应支持：

- 按 Work 标题搜索。
- 按 DOI 搜索。
- 按 `workId` 搜索。
- 按 `fileId` 搜索。
- 按正文块内容搜索。
- 搜索结果跳转到全文块定位位置。

建议优先级：中高。

## 前端缺口

### 2. 空状态和错误状态更具体

现状：多处只显示“加载失败”。

建议：

- 展示后端返回的 requestId。
- 展示错误原因。
- 对常见错误给下一步建议。
- 未登录、无权限、资源不存在、接口异常分别处理。

建议优先级：中。

### 3. 筛选体验继续收敛

现状：基础筛选可用，但还不够高效。

建议增加：

- 保存视图。
- 快捷筛选：“解析失败文件”“未匹配文件”“已解析未入库”。
- 已应用筛选的清晰摘要。
- 列表列显隐。

建议优先级：中。

### 4. 详情页上下文导航

现状：详情页缺少面包屑和回到筛选列表的上下文。

建议：

- 返回列表时保留筛选条件。
- 面包屑显示 Source / Work / Original File 上下文。
- 支持上一条/下一条。

建议优先级：中。

### 5. 视觉和信息层级

现状：整体仍有 Ant Design Pro 脚手架痕迹。

建议：

- 将异常状态作为第一视觉层级。
- 关键统计卡区分健康、警告、失败。
- 详情页把“用户能识别的名字”优先于内部 ID。
- 统一中文业务语言。

建议优先级：中。

## 后端缺口

### 6. Actuator / health / metrics

现状：已有管理台服务状态接口，但尚未接入 Spring Boot Actuator。

建议：

- 增加 `/actuator/health`。
- 暴露数据库、磁盘、应用版本健康信息。
- 接入基础指标。
- 前端服务状态页可继续消费这些接口或聚合接口。

建议优先级：高。

### 7. 登录限流和密码策略

现状：本地账号、session、CSRF 已具备，但安全策略仍偏基础。

建议：

- 登录失败次数限制。
- 短期账号锁定。
- 密码强度策略。
- 默认账号首次登录强制修改密码。
- session 过期提示。

建议优先级：中高。

### 8. 审计事件模型增强

现状：已有结构化 `admin_audit_log`。后续增强建议：

- 为 `action`、`targetType` 固定枚举和说明文档。
- 增加变更前后摘要。
- 增加导出和保留周期策略。

建议优先级：中。

### 9. 部署工件

现状：主要是本地运行文档。

成熟平台还需要：

- Dockerfile。
- docker-compose 示例。
- 环境变量完整说明。
- 日志目录说明。
- 健康检查配置。
- 构建产物部署说明。

建议优先级：中。

### 10. 只读边界产品化

现状：失败任务页已明确提示只读边界；其他页面仍可继续补充更一致的说明。

建议：

- 更多页面明确提示“当前管理台不触发 pipeline”。
- 失败详情页继续补充 CLI 处理方式。
- 对不可操作项展示原因，而不是简单隐藏。

建议优先级：中。

## 暂缓事项

以下能力不是当前阶段必须补：

- SSO / LDAP / OAuth。当前 ADR 已选择本地账号，短期合理。
- 动态权限矩阵。当前固定角色足够，除非出现多团队权限边界。
- 在线触发 pipeline。会打破只读边界，只有确认升级为运营控制台时才做。

## 建议下一步

下一步优先做三件事：

1. 全局搜索 / 块搜索。
2. 更具体的空状态和错误状态。
3. 登录限流、密码策略和 session 过期提示。

这三项继续保持只读架构，同时能明显提升排查效率和生产可用性。
